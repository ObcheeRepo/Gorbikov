# ConfigProject – Git Rebase и линейная история

Демонстрационный проект для отработки навыков работы с Git: инициализация репозитория, создание веток, выполнение ребейза для поддержания линейной истории и отправка изменений в удалённый репозиторий.

## Задача

1. Инициализировать локальный репозиторий в папке `ConfigProject`
2. Добавить файл `Config.cs` и закоммитить его
3. Создать ветку `config-update`, внести изменения и закоммитить
4. Выполнить ребейз ветки `main` на `config-update`
5. Убедиться в линейной истории коммитов
6. Подключить удалённый репозиторий и отправить изменения

## Исходные данные

- **Папка проекта:** `ConfigProject`
- **Файл:** `Config.cs`
- **Начальное содержимое:** `int config = 1;`
- **Изменение в ветке:** `int config = 2;`
- **Удалённый репозиторий:** `https://github.com/user/config.git`

## Пошаговое выполнение

### 1. Инициализация репозитория

```bash
cd ConfigProject
git init
```

Создаётся пустой Git-репозиторий в папке проекта.

---

### 2. Добавление файла `Config.cs` и первый коммит

```bash
git add Config.cs
git commit -m "Add Config.cs"
```

Файл с начальным значением `int config = 1;` зафиксирован в ветке `main`.

---

### 3. Создание ветки `config-update` и переключение на неё

```bash
git checkout -b config-update
```

Новая ветка создана от текущего состояния `main`.

---

### 4. Изменение файла `Config.cs`

Открываем `Config.cs` в любом редакторе и заменяем строку:

**Было:**
```csharp
int config = 1;
```

**Стало:**
```csharp
int config = 2;
```

---

### 5. Коммит изменений в ветке `config-update`

```bash
git add Config.cs
git commit -m "Update config value to 2"
```

Изменение зафиксировано в ветке `config-update`.

---

### 6. Выполнение ребейза

```bash
git checkout main
git rebase config-update
```

**Что происходит:**
- Переключаемся обратно на `main`
- Git перемещает указатель `main` на коммит ветки `config-update`
- Поскольку ветка `config-update` была создана от `main` и не было расхождений, ребейз выполняется как fast-forward

---

### 7. Проверка линейной истории

```bash
git log --oneline
```

**Ожидаемый вывод:**
```
abc1234 Update config value to 2
def5678 Add Config.cs
```

История линейная — два коммита идут последовательно без ветвлений и merge-коммитов.

---

### 8. Подключение удалённого репозитория

```bash
git remote add origin https://github.com/user/config.git
```

Проверить подключение:
```bash
git remote -v
```

**Вывод:**
```
origin  https://github.com/user/config.git (fetch)
origin  https://github.com/user/config.git (push)
```

---

### 9. Отправка изменений

```bash
git push -u origin main
```

Флаг `-u` устанавливает upstream-связь: в будущем для push/pull из ветки `main` достаточно будет писать `git push` без дополнительных параметров.

## Полезные команды Git (шпаргалка)

| Команда | Описание |
|---------|----------|
| `git init` | Инициализация нового репозитория |
| `git add <файл>` | Добавление файла в индекс |
| `git commit -m "..."` | Фиксация изменений |
| `git checkout -b <ветка>` | Создание и переключение на новую ветку |
| `git rebase <ветка>` | Перенос коммитов текущей ветки поверх указанной |
| `git log --oneline` | Просмотр истории в компактном виде |
| `git remote add origin <url>` | Подключение удалённого репозитория |
| `git push -u origin main` | Отправка ветки main на сервер с установкой upstream |

## Примечания

- **Ребейз вместо слияния:** Использование `git rebase` позволяет избежать создания лишних merge-коммитов и сохраняет историю линейной и чистой.
- **Fast-forward ситуация:** В данном случае изменения в `main` не происходили после создания ветки `config-update`, поэтому ребейз эквивалентен fast-forward слиянию.
- **Если бы были конфликты:** При наличии конфликтующих изменений потребовалось бы ручное разрешение конфликтов с последующим `git rebase --continue`.
